# 수익성·예측력 개선 계획

> 작성일: 2026-09-28
>
> 목적: 현재 자동매매봇을 더 복잡하게 만드는 것이 아니라, **미래에도 반복될 가능성이 있는 엣지를 찾고 실거래 수익으로 연결하는 과정**을 명확히 정의한다.
>
> 이 문서는 `UPDATE_LOG.md`의 기존 기록을 수정하지 않고, 앞으로 실행할 개선 방향과 판정 기준을 별도로 정리한 계획 문서다.

## 1. 현재 프로젝트의 핵심 진단

현재 가장 큰 문제는 신호가 부족하다는 것이 아니라 **백테스트의 기대값이 실거래 비용과 시장 변화에 의해 사라질 수 있다는 점**이다.

현재 확인된 상태는 다음과 같다.

- 탐색 구간 백테스트는 양수지만, 현재 설정은 OOS와 종목 집중도 게이트를 통과하지 못했다.
- 데모 및 실계좌의 순R은 아직 장기적으로 유의미한 수익을 입증하지 못했다.
- 건당 기대값이 작고 표준편차가 크기 때문에 월 +1% 목표는 단기간 거래 결과만으로 검증하기 어렵다.
- 편도 슬리피지 0.05R만 추가해도 결과가 크게 악화된다.
- TAO·SOL 등 일부 종목에 성과가 집중되어 있어 특정 종목·특정 시기의 운일 가능성을 배제하지 못한다.
- 현재 게이트는 과최적화를 막는 데 유용하지만, 네 구간 중 한 구간의 총R이 0 근처에서 흔들리는 경우 이진 판정의 영향을 크게 받는다.

따라서 당장 레버리지나 거래당 리스크를 늘리는 것은 우선순위가 아니다. 먼저 아래 질문에 답해야 한다.

> **실제 체결비용을 반영해도, 여러 시장·종목·시간 구간에서 반복되는 엣지가 남아 있는가?**

엣지가 확인되기 전 사이징을 늘리는 것은 수익 확대가 아니라 검증되지 않은 가설에 더 큰 금액을 거는 행위다.

## 2. 우선순위 원칙

### 원칙 1: 백테스트와 실거래의 차이를 먼저 줄인다

새로운 지표나 머신러닝 모델을 추가하기 전에 다음 항목을 백테스트와 실거래에서 동일하게 맞춘다.

- 수수료: 거래 등급·메이커/테이커·실제 체결 수수료
- 진입·청산 슬리피지
- 펀딩비
- 주문 지연
- 부분 체결 및 미체결
- 거래소 최소 주문수량·가격단위·명목가 제한
- 동시보유 한도와 서킷브레이커
- 신호 발생 시점에 이용 가능한 정보만 사용
- 동일한 포지션 사이징과 복리 기준

백테스트에 새로운 조건을 넣기 전에 먼저 **실제 주문을 재생할 수 있는 수준의 체결 데이터**를 확보해야 한다.

### 원칙 2: 높은 수익률보다 넓고 평평한 성능을 우선한다

파라미터 하나에서 최고값이 나온 것보다, 주변 값과 기간이 바뀌어도 성능이 유지되는 것이 중요하다.

좋은 후보는 다음과 같은 형태여야 한다.

- ADX 35에서만 급등하지 않고 30~40 범위에서 비슷한 결과
- 저변동 필터가 한 값에서만 통과하지 않고 일정 범위에서 유지
- 특정 종목 두 개가 전체 수익의 대부분을 만들지 않음
- 전반기·후반기·상승장·하락장·횡보장에서 성능 방향이 지나치게 뒤집히지 않음
- 비용 스트레스가 증가해도 손실 규모가 통제됨

### 원칙 3: 목표 수익률과 검증 기준을 분리한다

월 +1% 목표를 낮추거나 높이는 것은 자산 운영 목표의 문제다. 반면 전략이 미래에도 작동하는지는 별도의 검증 문제다.

월 +1%가 작다고 해서 다음을 허용하지 않는다.

- ���이트 기준 완화
- 홀드아웃 반복 사용
- 실패한 실험 삭제
- 특정 기간만 골라 성과 보고
- 실거래 손실을 백테스트 수익으로 상쇄해 해석

## 3. P0 — 실제 체결비용 측정과 백테스트 반영

가장 먼저 해야 할 일은 `actual_entry_price`를 이용해 실거래 비용을 정량화하는 것이다.

### 3.1 기록해야 할 값

거래마다 다음 필드를 보존한다.

- 신호 봉 종가
- 신호 생성 시각
- 주문 제출 시각
- 주문 제출 당시 시장가·호가 스프레드
- 실제 평균 진입 체결가
- 실제 평균 청산 체결가
- 체결 수량과 부분 체결 횟수
- 진입·청산 수수료
- 펀딩비
- 주문 지연 시간
- 신호 가격 대비 진입 슬리피지
- 목표 청산가 대비 청산 슬리피지
- `entry_slippage_r`, `exit_slippage_r`, `total_cost_r`

롱·숏의 슬리피지 부호가 다르므로 반드시 방향을 고려해 불리한 체결을 양수 비용으로 정규화한다.

### 3.2 분석 기준

최소한 다음 그룹별로 분포를 본다.

- 전체·심볼별
- 롱·숏별
- 시간대별
- 변동성 구간별
- 거래량·스프레드 구간별
- 신호 발생 후 체결 지연 시간별
- 시장 급변 구간과 평상시

평균만 보지 않고 중���값, 75·90·95퍼센타일, 최악 구간을 함께 기록한다. 실제 운영은 평균 비용이 아니라 꼬리 비용과 장애 상황에서 무너질 수 있다.

### 3.3 백테스트 비용 시나리오

고정된 단일 슬리피지 숫자 하나만 사용하지 말고 최소 세 가지 시나리오를 돌린다.

| 시나리오 | 의미 |
|---|---|
| 정상 | 최근 실측 중앙값 또는 보수적 평균 |
| 스트레스 | 실측 90퍼센타일 수준 |
| 장애 | 스프레드 확대·지연·불리한 체결이 겹친 상황 |

새 전략은 정상 시나리오에서만 수익이면 부족하다. 스트레스 시나리오에서도 손실이 제한되고, 장애 시나리오에서 계좌가 생존해야 한다.

### 3.4 완료 조건

다음 조건을 충족하기 전에는 실거래 리스크를 늘리지 않는다.

- 최소 100건 이상의 새로운 실거래 체결 데이터
- 백테스트 비용과 실측 비용의 차이를 설명 가능
- 심볼·방향별 비용 이상치 원인 파악
- 실측 비용을 반영한 게이트 재실행
- 과거 백테스트 수익이 아니라 실측 순자산곡선으로 확인

## 4. P1 — 진입 비용을 줄이는 실험

### 4.1 `MAX_ENTRY_PRICE_DRIFT_R` 추가 축소

현재 전략의 건당 기대값이 작다면, 신호 가격에서 크게 멀어진 뒤 진입하는 것은 기대값을 스스로 소모하는 행동이다.

다음 값을 사전 등록된 실험으로 비교한다.

- 0.05R
- 0.10R
- 0.20R
- 기존 기준값

각 실험에서 반드시 함께 기록한다.

- 거래 수
- 미진입 신호 수
- 순R
- 평균·95퍼센타일 슬리피지
- OOS 구간별 성과
- 종목 집중도
- MDD

거래 수가 줄어도 건당 기대값과 비용 후 성능이 개선되는지 확인한다. 거래량 감소 자체를 실패로 보지 않는다.

### 4.2 지정가 진입은 별도 전략으로 취급한다

시장가 진입을 지정가 진입으로 바꾸는 것은 단순한 최적화가 아니라 체결 메커니즘이 바뀌는 전략 변경이다.

백테스트에 다음 규칙을 명시한다.

1. 신호 확정 시 지정가를 제출한다.
2. 최대 대기 봉 수를 사전에 정한다.
3. 일정 시간 내 체결되지 않으면 주문을 취소한다.
4. 부분 체결은 실제 엔진과 같은 방식으로 처리한다.
5. 체결되지 않은 신호도 별도 이벤트로 기록한다.
6. 체결된 거래와 체결되지 않은 거래를 사후에 유리하게 선택하지 않는다.

지정가 백테스트에서 봉의 고가·저가가 주문가를 단순히 터치했다고 전부 체결시키면 낙관적 편향이 생긴다. 가능한 경우 하위 시간봉 또는 호가 데이터를 사용하고, 그렇지 않으면 보수적인 체결 규칙을 적용한다.

### 4.3 시장가·지정가 비교 기준

지정가 전략의 성공 조건은 수수료 절감이 아니다. 다음 순수익을 비교해야 한다.

```text
순기대값 = 체결된 거래의 수익
         - 미체결로 놓친 거래의 기회비용
         - 진입·청산 수수료
         - 실제 슬리피지
         - 부분 체결·주문 취소 비용
```

지정가 체결률이 낮아도 순기대값이 높을 수 있고, 체결률이 높아도 불리한 체결만 남는 선택편향이 생길 수 있다. 따라서 미체결 신호의 이후 가격 경로도 기록한다.

## 5. P2 — 롤링 워크포워드 심볼 선정

현재 12개 종목을 전체 기간 고정으로 사용하는 방식은 성과 집중도와 생존편향 문제를 남긴다. 심볼 선정도 파라미터와 동일하게 미래 정보가 차단된 워크포워드 구조로 바꾼다.

### 5.1 권장 구조

```text
학습 180일 → 테스트 30일
학습 210일 → 테스트 30일
학습 240일 → 테스트 30일
...
```

각 학습 구간에서만 다음을 수행한다.

- 거래 가능 유니버스 복원
- 최소 유동성·스프레드 조건 적용
- 개별 심볼의 비용 후 성능 계산
- 상관관계와 동시 손실 위험 계산
- 거래 수가 충분한 심볼만 후보로 유지
- 심볼을 선택하고 다음 30일 테스트에서 고정

테스트 구간이 끝난 뒤에 심볼을 다시 고르거나, 전체 기간 성과로 심볼 순위를 다시 매기면 미래 정보 누수가 된다.

### 5.2 심볼 선택 점수

총R 하나로 순위를 정하지 않는다. 예시는 다음과 같다.

```text
선택 점수 = 비용 후 기대R
         - λ1 × MDD 페널티
         - λ2 × 슬리피지 페널티
         - λ3 × 상관 노출 페널티
         - λ4 × 거래 수 부족 페널티
```

처음에는 복잡한 최적화보다 단순한 규칙을 권장한다.

- 최소 거래 수 미달 심볼 제외
- 비용 후 기대값이 음수인 심볼 제외
- 최근 학습 구간과 이전 학습 구간의 부호가 모두 양수인 심볼 우선
- 한 심볼의 포트폴리오 기여도 상한 설정
- 비슷한 움직임을 보이는 심볼을 동시에 과도하게 선택하지 않음

### 5.3 생존편향 처리

현재 거래 가능한 종목만 사용하면 상장폐지·거래중단·유동성 악화 종목이 사라지는 생존편향이 생긴다. 장기 검증을 위해 시점별 거래 가능 유니버스를 복원한다.

완전한 복원이 당장 어렵다면 최소한 다음을 문서화한다.

- 데이터에 포함되지 않은 종목 유형
- 상장 이후 워밍업 기간
- 거래소에서 제거된 종목 처리 방식
- 유동성이 낮아진 종목을 언제 제외했는지

## 6. P3 — 예측 모델을 추가할 때의 권장 방향

머신러닝을 추가하면 미래 예측력이 자동으로 좋아지는 것은 아니다. 현재 데이터 규모와 비용 구조에서는 먼저 **예측 모델을 진입 신호 생성기가 아니라 거래 필터·확률 추정기**로 사용하는 것이 안전하다.

### 6.1 1단계: 규칙 전략 위에 확률 필터

기존 규칙이 신호를 만든 뒤, 모델이 다음을 추정하게 한다.

- 다음 N개 봉 안에 +2R 도달 확률
- 손절 전 +1R 도달 확률
- 예상 보유 시간
- 예상 비용을 뺀 기대R
- 현재 시장 레짐

모델 출력으로 즉시 매수·매도를 결정하지 말고, 다음과 같이 사용한다.

```text
모델 기대값 = P(TP) × 순이익
            + P(SL) × 순손실
            - 예상 수수료
            - 예상 슬리피지

모델 기대값 > 최소 안전 마진일 때만 기존 신호를 허용
```

최소 안전 마진은 0이 아니라 실측 비용 오차와 모델 불확실성을 고려해 양수로 둔다.

### 6.2 입력 특성

입력값은 신호 시각에 실제로 알 수 있는 값만 사용한다.

- ATR 및 ATR/손절폭
- ADX, +DI, -DI
- 추세 방향과 추세 기울기
- 최근 수익률·변동성·거래량
- 스프레드와 호가 깊이
- 신호 발생 후 경과 시간
- 펀딩비·미결제약정 등 사용 가능한 시장 상태
- BTC 등 기준자산과 해당 심볼의 상대 움직임
- 동시 신호 수와 포트폴리오 현재 노출

미래 캔들의 고가·저가·종가를 특성 계산에 섞지 않는다. 피처 생성 코드에는 시점 기준 테스트를 둔다.

### 6.3 시계열 검증

랜덤 셔플 교차검증은 사용하지 않는다. 다음 구조를 사용한다.

- 확장형 또는 이동형 학습 창
- 바로 다음 기간 테스트
- 테스트 기간 결과를 모델 선택에 다시 사용하지 않음
- 여러 랜덤 시드와 비용 시나리오
- 모델 버전별 예측 분포 및 캘리브레이션 기록

예측 정확도보다 중요한 지표는 다음이다.

- 비용 후 기대R
- 예측 확률 구간별 실제 순R
- 캘리브레이션 오차
- 거래 수 감소 후 남은 거래의 안정성
- 시장 레짐별 성능
- 모델이 꺼졌을 때와 켜졌을 때의 차이

### 6.4 금지할 것

- 전체 데이터로 라벨을 만든 뒤 랜덤 분할
- 테스트 기간 성과를 보고 모델 구조 변경
- 수십 개 모델 중 최고 모델만 보고
- 모델 확률을 근거 없이 레버리지 증가에 사용
- 설명할 수 없는 입력값과 데이터 누수
- 모델 성능이 나쁘면 라벨·기간·게이트를 계속 바꾸는 것

## 7. P4 — 동적 사이징은 가장 마지막에 한다

사용자가 위험을 감수할 의사가 있더라도, 동적 사이징은 전략의 엣지가 확인된 이후에만 적용한다.

### 7.1 권장 단계

1. 고정 리스크 0.10~0.25%로 비용 후 엣지 검증
2. 최소 3개월 이상 실거래 순자산곡선 관찰
3. 게이트·홀드아웃·실측비용 조건 통과
4. 변동성·상관관계에 따른 노출 상한 검증
5. 그 후에만 0.25% → 0.50%처럼 단계적으로 증가

현재처럼 전략 자체가 게이트를 통과하지 못한 상태에서는 0.75% 또는 그 이상으로 올리지 않는다.

### 7.2 사이징 상한

동적 사이징을 구현하더라도 다음 상한을 둔다.

- 거래당 최대 손실률
- 전체 포트폴리오 최대 동시 손실률
- 심볼군별 최대 노출
- 동일 방향 노출 상한
- 하루 최대 손실
- 주간·월간 손실 중지선
- 변동성 급등 시 자동 축소

사이징 계산 실패, 잔고 조회 실패, 주문 보호 실패가 발생하면 신규 진입을 차단하는 쪽이 안전하다.

## 8. 게이트 개선 방향

현재 `src/backtest/gate.py`의 고정 게이트는 과최적화 방지에 중요한 장치이므로 결과에 맞춰 즉시 완화하면 안 된다.

다만 이진 OOS 통과 여부를 보조하는 연속 지표를 추가할 수 있다.

### 8.1 기존 게이트 유지

기존 게이트는 계속 별도 기록한다.

- 분할별 양수 여부
- `total_r_p5`
- 회복계수
- 상위 2개 심볼 집중도
- 양수 심볼 비율
- 스트레스 비용 성과

### 8.2 추가로 기록할 연속 지표

- 최악 분할의 총R
- 분할별 중앙값과 분산
- 분할별 거래 수
- 분할별 비용 후 기대R
- 심볼별 성과의 분산
- 부트스트랩 신뢰구간
- 최악 5% 경로의 MDD
- 손실 구간의 최대 연속 길이

새로운 통과 기준을 만들 때는 반드시 `GATE_VERSION`을 올리고, 기존 결과와 섞지 않는다. 권장 방식은 기존 게이트를 유지하면서 연속 지표를 **채택 우선순위와 보류 판정**에 사용하는 것이다.

예를 들어 최악 분할이 -0.4R인 후보와 -15R인 후보를 둘 다 단순히 FAIL로 처리하지 않고, 다음 단계의 우선순위를 다르게 줄 수 있다. 하지만 이 보조 지표가 기존 게이트를 우회하는 통로가 되어서는 안 된다.

## 9. 실거래 배포 단계

새로운 전략 또는 모델은 다음 네 단계를 거친다.

### 단계 A — 오프라인 검증

- 고정된 탐색·검증·홀드아웃 구간
- 실측 비용 반영
- 롤링 워크포워드
- 여러 시드
- 심볼 선정 누수 검사
- 데이터 누수 테스트

### 단계 B — 그림자 운영

실제 시세와 주문 데이터를 사용하되 주문은 제출하지 않는다.

- 신호
- 예상 체결가
- 실제 당시 호가
- 가상 체결 여부
- 예상 슬리피지
- 모델 판단
- 실제로 놓친 거래의 이후 경로

을 모두 기록한다.

### 단계 C — 최소 금액 실거래

기존 목표 리스크의 일부만 사용한다. 이 단계의 목적은 수익 극대화가 아니라 다음을 확인하는 것이다.

- 체결 비용
- 주문 보호
- API 오류 복구
- 포지션 동기화
- 브레이커 동작
- 로그와 자산곡선 일치

### 단계 D — 제한적 확대

다음 조건을 모두 만족할 때만 사이징을 조금씩 확대한다.

- 최소 3~6개월의 순자산 데이터
- 비용 후 양수 또는 사전 정의한 허용 범위
- 백테스트와 실거래 비용 차이 설명 가능
- 치명적 주문 오류 없음
- 최대낙폭이 사전 한도 안
- 단일 심볼·단일 레짐 의존도 완화

## 10. 8주 실행 계획

### 1~2주차: 관측 기반 정비

- 실거래 진입·청산 슬리피지 리포트 작성
- 수수료·펀딩비 분리
- 주문 지연과 부분 체결 기록
- `MAX_ENTRY_PRICE_DRIFT_R` 후보 실험 등록
- 정상·스트레스·장애 비용 시나리오 정의
- 미체결 신호 저널링

### 3~4주차: 체결 모델 개선

- 지정가 진입 백테스트 추가
- 하위 시간봉 또는 보수적 체결 모델 추가
- 시장가·지정가 순기대값 비교
- 실측 비용으로 게이트 스트레스 기준 갱신
- 기존 게이트는 유지하고 새 결과를 별도 버전으로 기록

### 5~6주차: 롤링 심볼 선정

- 학습·테스트 분리 구조 구현
- 학습 구간 내 유동성·비용·성과 기반 심볼 선택
- 종목 집중도와 상관 노출 제한
- 시점별 유니버스와 생존편향 문서화
- 30일 단위 테스트 결과만 집계

### 7주차: 예측 모델 그림자 운영

- 기존 신호를 입력으로 하는 확률 필터의 오프라인 실험
- 랜덤 분할 금지, 롤링 검증만 사용
- 모델 출력과 실제 결과 비교
- 모델을 켜고 끄었을 때의 순R·거래 수 비교

### 8주차: 배포 판정

- 게이트 및 홀드아웃 판정
- 실측 비용 반영 후 수익성 확인
- 최소 금액 실거래 여부 결정
- 실패하면 리스크를 늘리지 않고 원인 분류
- 통과해도 즉시 큰 금액으로 확대하지 않음

## 11. 성공·실패 판정 기준

### 성공에 가까운 증거

- 실측 비용을 반영해도 여러 기간에서 기대R이 양수
- 특정 파라미터 한 점이 아니라 주변 범위에서 성능 유지
- 특정 두 종목에 의존하지 않음
- 스트레스 비용에서 손실이 통제됨
- 롤링 테스트의 여러 창에서 성능 방향이 일관됨
- 그림자 운영의 예상 체결과 실제 체결 차이가 작음
- 실거래 순자산곡선이 백테스트의 비용 후 경로와 크게 다르지 않음

### 전략 교체를 검토해야 하는 증거

- 실측 비용을 반영하면 기대값이 0 이하
- 최근 여러 롤링 창에서 반복적으로 음수
- 심볼을 바꿔도 특정 종목에만 의존
- 홀드아웃에서 실패한 뒤 기준을 바꿔야만 통과
- 실거래 3~6개월 동안 비용 후 자산이 증가하지 않음
- 모델을 추가할수록 검증 구간만 좋아지고 미래 구간은 악화

이 경우 목표 수익률을 더 낮추는 것이 해결책이 아니다. 전략의 엣지가 없다는 문제와 목표 수익률의 문제를 분리해, 다른 시장·시간봉·전략 구조를 검토한다.

## 12. 최종 권고

가장 공격적인 선택은 레버리지를 높이는 것이 아니라, **실제 비용과 실패 상황을 정직하게 모델링한 뒤 그 조건에서도 살아남는 전략만 남기는 것**이다.

이 프로젝트의 다음 성장 순서는 다음이 가장 합리적이다.

```text
실측 체결비용
→ 비용 반영 백테스트
→ 진입 체결 방식 개선
→ 롤링 심볼 선정
→ 비용 후 확률 필터
→ 그림자 운영
→ 최소 금액 실거래
→ 장기간 검증 후 제한적 사이징 확대
```

특히 지금은 다음 세 가지를 하지 않는다.

1. 게이트를 낮춰 현재 설정을 통과시키지 않는다.
2. 실거래가 아직 수익을 입증하지 못한 상태에서 거래당 리스크를 늘리지 않는다.
3. 머신러닝 모델을 추가했다는 이유만으로 미래 예측력이 좋아졌다고 가정하지 않는다.

**목표는 거래를 많이 하는 봇이 아니라, 비용·시장 변화·운영 장애를 견디면서 장기간 순자산을 증가시키는 시스템이다.**
